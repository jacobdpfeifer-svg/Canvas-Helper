## Structural proposals

### 1. Re-sign Tauri “parked” vs active dock/onboarding surface
- **Observed:** Architecture + pre-ship decision (2026-09-12) say Desktop shell is Parked — “do not expand features.” Meanwhile study-optimizer dock IPC shipped and onboarding/`save_user_profile` are mid-flight in `app/`.
- **Why it matters:** Agents treat “parked” as a hard stop; product work already lands there → claim/discipline drift.
- **Concrete change:** Sign either (A) “park shell *rewrite*; dock/onboarding/learn-loop IPC in-scope” and update architecture L29 + pre-ship row, or (B) freeze `app/` and move identity writes to a CLI-only path.
- **Size/risk:** small (docs + decision) | needs a real plan if (B).
- **External note:** Upstream [vishalsachdev/canvas-mcp](https://github.com/vishalsachdev/canvas-mcp) has no desktop shell — ProductName’s dock is original surface area, so “parked” must be a ProductName decision, not an upstream sync concern.

### 2. Freeze one `user_root` contract across JS / Python / Rust
- **Observed:** `browser/scripts/lib/user-root.mjs`, `canvas_mcp.core.user_root`, and `app/src-tauri/src/inbox.rs` reimplement resolution; create-subdir sets and product-name hardcoding drift.
- **Why it matters:** Sync vs daemon vs peek can land in different trees under edge env cases — splits the truth path.
- **Concrete change:** Canonicalize on Python `user_root.py`; cross-runtime fixture asserting `DEV_USER_ROOT` / app-support/`dev` agreement; align create subdirs (`inbox/learn` at minimum); stop hardcoding `"ProductName"` in Rust.
- **Size/risk:** small.

### 3. Shared inbox contract for course stems / week rows / checkpoints
- **Observed:** `resolveCourseFile`, `classifyOutcomeHint`, `isCheckpoint` live in browser sync; `learn_loop` re-parses `week.md` with a thinner quiz/exam marker set.
- **Why it matters:** Post-sync reconcile/due-reviews can disagree with what sync labeled — silent dock wrongness.
- **Concrete change:** Shared “inbox contract” (JSON schema export from sync, or Python port of stem + checkpoint rules) + golden fixtures asserted from both runtimes.
- **Size/risk:** needs a real plan.

### 4. Live MCP refresh must write inbox, not bypass it
- **Observed:** Truth path is Skill ← inbox ← SSO `/api/v1` (PAT optional). Skills still allow live due-list/grades MCP as a normal read path without mandating the sync-shaped writers. Browser sync itself correctly uses SSO cookies → `/api/v1` (no Canvas assignment-page DOM scrape found).
- **Why it matters:** Agent brief and dock/learn_loop diverge in one session.
- **Concrete change:** Skill + `prompt_assembly` policy: live MCP only to *refresh* inbox writers; `Source:` stays `sso-session-api|mcp|manual paste`. Optional later: code helper that materializes week/grades rows.
- **Size/risk:** small (policy) | needs a real plan (enforced writeback).
- **External note:** Upstream canvas-mcp is PAT-first tool surface (~80–100 tools, educator+student, optional `execute_typescript` bulk path). This repo’s inbox-as-memory is the ProductName differentiator — shortcuts that re-center live MCP erode it. Upstream has no SSO→inbox layer to protect.

### 5. Slim skill-router overlaps and stale WRITE/RELIABLE sets
- **Observed:** 14 skills load dynamically (good). Strain: week-plan ↔ task-brief briefing overlap; degree-progress / course-plan / registration-prep / gpa cluster; `RELIABLE_SKILL_IDS` + frontmatter dual tier; `WRITE_SKILL_CATEGORIES` includes dead Canvas-visible write categories.
- **Why it matters:** Ambiguous routes + misleading “reliable write” signal for paths that must never execute.
- **Concrete change:** Collapse shared briefing into one include (or schedule-only week-plan → handoff to brief); tier from frontmatter only; drop forever-preview categories from WRITE set (keep `email_send` / real connector writes). Add routing eval fixtures first.
- **Size/risk:** small–needs a real plan.

### 6. Split product core package from vendored MCP tree
- **Observed:** `vendor/README.md` wants ProductName features outside the vendored fork; reality is `learn_loop`, `skill_router`, `gpa`, `user_profile`, `claim_context`, … living under `src/canvas_mcp/core/` beside vendored `tools/` + `client.py`. Root `CHANGELOG.md` remains upstream-owned. Upstream continues shipping educator tools, Learning Designer skills, and code-execution APIs this fork deliberately strips.
- **Why it matters:** Upstream bumps collide with ProductName brain PRs; “is this fork or product?” stays ambiguous; merge cost rises with every core module added under the vendored package path.
- **Concrete change:** Mechanical package split (`src/productname/` or similar) + thin re-exports; keep ProductName history in `docs/handoff/`, not a second CHANGELOG.
- **Size/risk:** needs a real plan.

### 7. Align CampusGroups confirm strength with ConfirmationGuard (when MCP arrives)
- **Observed:** Gmail/GCal use fingerprint-bound single-use tokens via `gate_connector_write` → `get_connector_guard`. CampusGroups RSVP CLIs accept forgeable `--confirm` / `{confirmed: true}`.
- **Why it matters:** Organizer-visible RSVP is the pivot’s explicit exception; boolean confirm is weaker and will drift when RSVP becomes an MCP tool.
- **Concrete change:** MCP writes must use `get_connector_guard` (registry already requires it). CLI: either short-lived preview fingerprint token, or document “human-at-keyboard only” and ban agent-invoked RSVP without the guard.
- **Size/risk:** small (docs) | needs a real plan (CLI token parity).
- **External comparisons (tool-gating shapes):**
  - [mcp-policy-guard](https://github.com/mughalhere/mcp-policy-guard) — middleware returns `confirmation_required` + single-use token bound to tool name + argument hash + identity (TTL ~5m). **Maps almost 1:1** onto `ConfirmationGuard` / `gate_connector_write`; this repo already has the stronger local-first variant (HMAC content fingerprint + `ledger.jsonl`). Do not replace with a generic proxy — keep the in-process guard; optionally borrow their “denied tools disappear from `tools/list`” for forever-preview Canvas tools so agents stop probing execute.
  - [mcp-approval-proxy](https://github.com/vaddisrinivas/mcp-approval-proxy) / [mcp-guard](https://github.com/alan-provable/mcp-guard) / [mcpgate](https://github.com/maksym-mishchenko/mcpgate) — sit *outside* the server and gate by name/annotation/YAML. Useful for multi-server desktops; overkill for ProductName’s single-user local actuators, and would not encode the canvas-focus “preview forever, no redeem” rule without custom deny lists.
  - [MCP elicitation](https://docs.mcp-agent.com/concepts/elicitation) (`ctx.elicit`) — protocol-native pause. Worth watching if Tauri dock becomes the confirm UI; today’s string-preview + token round-trip is intentionally client-agnostic.

### 8. Cross-runtime inbox-contract tests (unit thick, chain thin)
- **Observed:** Strong unit/security coverage (`tests/core/*`, `tests/security/test_student_write_invariants.py`, browser node tests). Thin: fixture Canvas JSON → sync writers → Python `learn_loop`/`gpa`/`prompt_assembly` on the *same* files; daemon-spawned sync under `DEV_USER_ROOT`.
- **Why it matters:** Proposal 3 will keep regressing without a shared golden fixture.
- **Concrete change:** `tests/fixtures/inbox_contract/` golden week.md + grades.yaml + course md; Python asserts; optional JS/Python/Rust `user_root` smoke.
- **Size/risk:** small.

### 9. Shared USER.md section helper (keep modules in core)
- **Observed:** `learning_profile.py` and `user_profile.py` each private-copy seed/section-replace for different `##` headings. Skills correctly stay instruction-only; app correctly shells via daemon.
- **Why it matters:** Onboarding order can race or duplicate sections.
- **Concrete change:** Extract `user_md.py` section replace/seed; keep writers in core; app stays thin IPC.
- **Size/risk:** small.

### 10. Canonical-writer matrix in architecture
- **Observed:** Dual surfaces already confuse audits: `week.md` vs live MCP vs `focus.md`; `grades.yaml` vs MCP grades; `USER.md` vs `learning-profile.yaml`; course `## Checkpoints` vs `checkpoint_due`.
- **Why it matters:** Every new skill/dock feature invents another reader without a sole-writer rule.
- **Concrete change:** One table in `docs/architecture.md`: path → sole writer → allowed readers → never-writer. Point skills + app IPC at it.
- **Size/risk:** trivial–small.

### 11. Permissions schema: drop or freeze forever-preview categories
- **Observed:** Finding #6 — `canvas_submit` / `canvas_discussion_post` still look escalatable in `permissions.py` while tools are permanently preview-only.
- **Why it matters:** A future agent or UI that reads the posture matrix could reintroduce an execute path “because DEFAULT_K says gated.”
- **Concrete change:** Mark those categories `preview_only` / remove from `DEFAULT_K`, or assert in tests that no tool registers an execute branch for them.
- **Size/risk:** small.
