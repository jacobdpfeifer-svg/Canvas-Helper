# Blot animation plan (2026-09-30)

Blot is the ink-drop voice character chosen on 2026-09-30. Prototypes: options page https://claude.ai/artifact/3yKXN3QbEbSWiMqvLb2Qjo, Blot traits page https://claude.ai/artifact/25NbVuvRHqqACk1q9evLNf. This doc says how Blot is animated in the product and where the code goes.

**Status (2026-09-30): built.** Engine, app voice sheet, extension side-panel Blot, pixel icons, and Canvas course colours are in. The one open step is wiring the real voice model into `app/src/voice/presence.ts` (it was not in the checkout on 2026-09-30); until then `?blot` in a dev build plays a scripted exchange. The MASTER.md §08 amendment landed with the build.

## Decision: code-driven soft body, not Rive

| Approach | What it is good at | Why not (or why) for Blot |
|---|---|---|
| Soft-body physics in code (chosen) | Liquid squash, jiggle, volume that stays constant, reacting to any audio level | Expressions are authored as numbers, not drawn by an animator |
| Rive state machine (Duolingo) | Hand-animated acting, visemes, designer-owned timing | Bones and keyframes do not produce a liquid outline; ~200 KB gz WASM; the extension would need `wasm-unsafe-eval` on extension pages and it is unclear on the Canvas-page content script |
| Lottie | Fixed clips | Cannot follow live audio |
| WebGL noise shader (voice-orb components) | Glowing liquid orbs | That is the "glow orb" MASTER §12 bans, and it has no face |
| Generated video (Higgsfield/Veo) | Marketing | Fixed pixels; cannot react |

Revisit Rive only if Blot needs acting beyond the pose table below. If that happens, the face could move to Rive while the body stays in code.

## How good blobs move (what we copy)

1. **Pressure soft body.** A ring of points joined by springs, plus an internal pressure force that keeps the area constant (JellyCar's `PressureBody`, LocoRoco). Squashing one way makes it bulge the other way on its own.
2. **Shape matching toward a rest pose.** Pure pressure bodies turn round. A weak pull toward the rest silhouette keeps the nib tuft.
3. **Anticipation → action → follow-through.** Crouch before the done-hop, pinch the tuft before each drop leaves, overshoot and settle on landing.
4. **Secondary motion from springs, not keyframes.** The nib lags the body; eyes lag the head by ~60 ms.
5. **Smoothed audio level.** RMS with 30 ms attack / 150 ms release and a noise gate. Raw amplitude twitches and reads as broken.
6. **Holds.** Idle is nearly still: breathe (~0.6 Hz, 2% scale) and blink (every 2.5–5.5 s, 150 ms). MASTER §09: motion only on real state.
7. **Mouth from level first, visemes later.** Copilot's Mico and ChatGPT's Dots use amplitude. Duolingo maps visemes. Add visemes only if the TTS engine emits them.

## Architecture (as built)

```
voice model ──► app/src/voice/presence.ts
                  voicePresence.set({ state, transcript, status, reply, items })
                  attachAnalyserLevel(analyser) / createRmsFeeder()   ← level, outside React
                  voicePresence.onStop(fn)                            ← Stop button
                         │
                         ▼
   app/src/blot/core/   (dependency-free ESM + index.d.ts; source of truth)
     body.js      pressure soft body: 48 points, shape matching, edge springs, gas pressure, 120 Hz substeps
     machine.js   voice state → pose, face, course-colour bands, events (land, stretch, pinch, poke, stamp);
                  anticipation, done-hop, drops, dozing, seeded blink
     timeline.js  answerTimeline(items): shared clock for drops and handwriting
     level.js     RMS → gated, 30 ms attack / 150 ms release level
     render.js    Canvas2D: Catmull-Rom outline, destination-out eyes/mouth/nib, low liquid bands, stamp ring
     engine.js    createBlot(): update(input, dt, {still}) + draw(ctx, w, h, colors)
     poses.js     tuned numbers per state
                         │
         ┌───────────────┴──────────────────────────┐
         ▼                                          ▼
 app/src/blot/Blot.tsx, BlotAnswer.tsx,      app/extension-chrome/shared/blot/  (generated by
 VoiceSheet.tsx (mounted in App.tsx)          tools/vendor-shared.mjs, drift-tested)
                                              lib/blot-mount.js → side-panel header
```

- **Rendering:** Canvas2D. The loop pauses off-screen (IntersectionObserver), when the window is hidden, and in reduced motion; the first frame is drawn synchronously.
- **Handwriting is DOM text** (`BlotAnswer`): per-character spans that go from `--ink` (the course colour) to `--fg`, a visually-hidden full line for screen readers, and bullets that fly from Blot via the Web Animations API.
- **Reduced motion:** `data-motion="reduced"` or `prefers-reduced-motion` → `still` mode: one held pose per state, no physics, no hop, no blink, and the whole answer at once.
- **Course colours:** sync does one read-only `GET /api/v1/users/self/colors` → `{user_root}/inbox/courses/colors.json` (`browser/scripts/lib/course-colors.mjs`); Tauri `read_course_colors` → `readCourseColors()`; `withCourseColors()` fills `item.color` from `item.courseId`. The extension does not fetch colours (its Canvas allow-list is unchanged).
- **Icons:** `app/extension-chrome/tools/blot-icons.mjs` writes the 16×16 pixel Blot to `icons/blot-{16,32,48,128}.png` (`--check` for staleness).

## Tests

- `app/src/blot/core/core.test.ts`: area within 5% after a hard landing, settles in 1.5 s, visible jiggle, determinism, nib stays the top point, floor contact; done-hop lands and stamps once; one pinch per item and refill; bands soak in, drain per drop, and clear after; dozing and waking; syllable stretch; still mode has no events; level meter; timeline; a full exchange with no NaN.

## Wiring the voice model (remaining)

1. Call `voicePresence.set({ state })` on every session transition; `listening` clears the previous turn.
2. `attachAnalyserLevel(micAnalyser)` while listening, then the playback analyser while speaking (or `createRmsFeeder()` if the engine reports RMS).
3. With the reply, pass `items: [{ title, courseId, due }]` for anything the answer lists; Blot gives one drop per item.
4. `voicePresence.onStop(() => session.stop())` so the sheet shows Stop.
